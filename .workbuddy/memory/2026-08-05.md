## 浏览器插件实现逻辑完整分析（用户要求：不写测试，直接分析找明显问题）
已完成全量代码走读（types/lib/bridge/worker/rpc/content）。确认的问题（按严重度）：

**功能性缺陷**
1. `src/types/schema-graph.ts:98-104` `normalizeIdentifier`：`key` 两分支都 `raw.toLowerCase()`，`quoted` 形同虚设 → 带引号的大小写敏感标识符会被强制小写，扭曲 Postgres 语义；`identifierMatches` 对 quoted 也走 `toLowerCase()` 比较，同样问题。
2. `src/lib/ddl-parser.ts:236-238` PK 标记：`table.primaryKey.includes(col.name)` 用原始名比对；约束式 PK（`readParenColumns` 返回原始名）与列定义大小写不一致时，`isPrimaryKey` 不会置真 → 主键列标记丢失。应统一用 `.toLowerCase()`（如 `col.key`）比对。
3. `src/content/content-script.ts:843` `quickDetectDangerSync` 用正则重复实现 `danger-detector.ts` 的 `detectDanger`，两者逻辑分叉（同步版不剥 `/* */` 之外的注释细节、无 token 级精度），同一 SQL 可能得出不同结论；且有死变量 `void upper`。
4. `src/content/content-script.ts:250` `findEditorDomFor` 靠 `document.activeElement` 命中 `.cm-editor`，pgAdmin4 多 Query Tool 标签时可能绑错编辑器（作者注释已承认不完善）。

**整洁度/死代码（不影响功能）**
5. `src/worker/parser-worker.ts:95-96` `jsonb-tree` 解构出 `table` 但从未使用；关系键查找实际用 `req.relationKey.toLowerCase()`（与存储键一致，功能正确，仅死变量）。
6. `src/lib/ddl-parser.ts:511-512` `findColumnOptionStart` stopKws 中 `REFERENCES` 重复。
7. `src/lib/ddl-parser.ts:131` `kw === "GRANT" || kw === "REVOKE" || kw === "REVOKE"` 冗余 REVOKE。

**安全/设计弱点**
8. nonce 鉴权被 CustomEvent 泄露：`content-script.ts:165` 用 `new CustomEvent("pg4:init", {detail:{nonce}})` 向 MAIN world bridge 传递 nonce；任意同源页脚本（pgAdmin4 自身 JS 或 XSS）可 `addEventListener("pg4:init")` 读到 nonce，伪造 `apply-completion` 等 ExtensionToBridgeMessage 向编辑器注入任意文本。nonce 对同源页脚本形同虚设；仅能挡住不共享 window 的 ISOLATED world 脚本。因扩展不连库/不读凭据，爆破半径有限，但仍属设计弱点。（report 中用 §安全 详述）

详见本次对话最终分析报告。

## 最小修复实施（PG 大小写敏感 / 双引号标识符 / 单引号字符串）

- `parser-worker.ts`：删 `jsonb-tree` handler 中未使用变量 `table`。
