### 本机推送通道（本次的主要非显然结论）

- `git push origin main`（origin = gh-proxy 镜像）**失败**：
  `remote: Invalid username or token. Password authentication is not supported for Git operations.`
  —— 凭据管理器里 gh-proxy 那份凭据是密码型，GitHub 已不支持 git 密码认证。
- 排查：`gh` CLI 未安装（插件 `yeet` 技能因此不可用）；Trae code-mode 沙箱内 `run_mcp` 看不到插件 MCP server；
  转而实测网络——`curl https://github.com` 直连 200（`$env:https_proxy` 为空），
  `git credential-manager github list` 显示 GCM 里存有有效账号 `HalZheng`。
- 解决：`git remote add github https://github.com/HalZheng/pg4-assist.git` → `git push github main` **成功**，
  本地两个 commit 的 SHA 原样保留（`0e49cfe..04603ee`）。
- 验证：`git ls-remote github main` = `04603ee`，`git diff github/main` 为空；
  随后 `git fetch origin` 后 `origin/main` 也同步到 `04603ee`（gh-proxy 读路径正常、不滞后）。
- 结论已写入 `pitfalls.md`（推送通道、gh/sandbox 两条）与 `decisions.md`（本机远端更新）。
  **失效条件**：gh-proxy 凭据换成 PAT、或凭据管理器被清空 / 换机器后，需按 `git remote -v` 与实测重测。
