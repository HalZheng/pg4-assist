## 给冒烟 agent 的提示词（整段复制）

```text
你在有真实 pgAdmin 4 的环境里，对注入脚本 pg4-assist.js 的新版本 v2.4.0 做冒烟测试。
注入方式与既往一致：F12 → Sources → Snippets → 粘贴 pg4-assist.js 全文 → 在顶层页面上下文 Ctrl+Enter。

【启动自检】
0. Console 过滤 "pg4"，应看到「PG4 Assist v2.4.0 已启动」。旧版本已跑过也没关系，
   本次 GRID_HOOK_REV 已从 11 升到 12，重跑会自动重装结果网格的 hook。

【准备数据】在 Query Tool 执行并查询（ producing 边界值：逗号/引号/换行/NULL/jsonb/bigint ）：
    DROP TABLE IF EXISTS pg4_smoke;
    CREATE TABLE pg4_smoke (id bigint PRIMARY KEY, name text, score numeric,
                            active boolean, meta jsonb, note text);
    INSERT INTO pg4_smoke VALUES
      (1, 'Zhang, San', 3.14, true,  '{"x":1,"y":"a,b"}', E'says "hi"\nbye'),
      (2, NULL,         7,    false, NULL,            'a|b'),
      (3, 'Li Si',      NULL, true,  '[1,2]',        'plain'),
      (9007199254740993, 'bigint 边界', 0, false, '{}', '');
    SELECT * FROM pg4_smoke;

【A 组：右键菜单导出格式】
在结果网格选中若干单元格/行/列 → 右键。菜单应出现三组：
「复制选项」(列名和数据/仅数据/仅列名) ｜ 新增「导出格式」(CSV/JSON/Markdown，JSON 项右侧有行数徽标) ｜「SQL 片段」(IN 条件)。

A1 复制为 CSV → 粘到文本编辑器（或 Excel）：
   - 逗号分隔、第一行是表头、行尾是 CRLF；
   - "Zhang, San"、meta、note 这类含逗号/引号/换行的单元格被双引号包裹、内部引号翻倍（RFC 4180）；
   - NULL 输出为空字符串（第 2 行 name、meta 为空）；
   - Excel 打开时 1 行 6 列对齐，无错位。
A2 复制为 JSON → 粘到编辑器做 JSON.parse 必须通过：
   - 对象数组，每个对象一行；键为列名；
   - id=1/2/3 转成数字，id=9007199254740993 保持字符串（防精度丢失）；
   - score 是数字、active 是 true/false、NULL 是 null；
   - meta 为嵌套对象（fiber 提取）或合法 JSON 文本字符串（DOM 兜底提取），两者都算 PASS。
A3 复制为 Markdown → 粘到支持 GFM 的编辑器预览渲染成表格：
   - 表头 6 列 + 分隔行 + 数据行；note 里的 | 转义为 \|、换行显示为 <br>，不破坏列数。
A4 回归：Ctrl+C / 右键原有三项（列名和数据/仅数据/仅列名/IN 条件）行为与 v2.3.0 一致；
   单单元格 Ctrl+C 仍去外层引号。
A5 什么都不选时右键单元格之外区域 → 不弹菜单；选中后逐项点击 → toast 文案分别为
   「已复制 CSV / 已复制 JSON / 已复制 Markdown」。

【B 组：语句级列作用域（补全行为，本次有 1 处有意的行为变化）】
先在面板里导入包含两张表的 DDL 快照（列名要能区分，如 a_table(a_col1,a_col2) 与 b_table(b_col1,b_col2)）。
同一查询窗口里逐条验证（光标位置用 ‸ 标出）：

B1 基线：SELECT * FROM a_table WHERE ‸ → 只弹 a_table 的列，不出现 b_table 列。
B2 多语句互不污染（核心）：两条语句并排
     SELECT * FROM a_table WHERE ‸;  SELECT * FROM b_table WHERE ‸
   第 1 处只弹 a_table 列，第 2 处只弹 b_table 列。
B3 【有意的行为变化，重点确认】语句还没写 FROM：
     SELECT * FROM a_table;
     SELECT ‸
   光标处**不再出现任何表的列**（旧行为会给全库列名兜底），只剩关键字/表名/函数。
   请确认这种「宁缺勿错」的行为可接受；若希望保留旧行为，反馈时注明「恢复全库列兜底」。
B4 引用的表不在快照里：SELECT * FROM not_in_snapshot WHERE ‸ → 不弹全库乱列。
B5 显式限定符保留：不写 FROM 直接 SELECT b_table.‸ → 照常弹 b_table 列。
B6 CTE：WITH t AS (SELECT * FROM a_table) SELECT * FROM ‸ → FROM 位置照常给全库表名（未改动），
   不报错、不崩；SELECT t.‸ 可回落 pgAdmin 原生补全或为空，均算 PASS，不得弹无关库表列。
B7 子查询：SELECT * FROM a_table WHERE a_col1 IN (SELECT b_col1 FROM b_table WHERE ‸)
   → 同一语句内，a/b 两表列都应弹出。
B8 既有特性回归：JOIN 后 ON ‸ 仍优先给外键/推断连接条件；INSERT INTO a_table (‸) 仍给列清单；
   排序字段后输 DESC/ASC 仍有联想；SELECT 列表后 FROM 权重靠前。
B9 性能抽查：把上述脚本复制几遍凑成大文档（>5000 行更佳），光标来回移动输入，
   输入延迟与 v2.3.0 无可感知差别。

【反馈格式】
逐条回 PASS/FAIL；FAIL 附：操作步骤、Console 报错（过滤 pg4）、剪贴板实际内容或截图。
A 组任何 FAIL → 指出是哪个格式化分支（csv/json/markdown）；
B3 若判定为不可接受，明确说「恢复全库列兜底」，其余 FAIL 不受它影响。
```

## 背景（给人工审阅者）

- **改动范围**：`pg4-assist.js` v2.3.0 → v2.4.0，+104/-16。
  1. 导出格式：`GRID_HOOK_REV` 11→12；hook 内新增自包含 formatter（不依赖 pgAdmin CsvHelper，定位失败也可用）；右键菜单新增「导出格式」组。CSV 对标 DBeaver/DataGrip：含表头、逗号分隔、RFC 4180 转义、CRLF（Excel 友好）。
  2. 语句级列作用域：`collectScope` 新增 `stmtRefs`（语句内表名引用，无论能否解析）；删除 `buildCandidates` 里 `!scopeList.length` 时的全库列名兜底——列候选严格限定为当前语句涉及的表。
- **本机已验证**：`node --check` 通过；从源文件提取真实 formatter 代码跑断言全 PASS（RFC 4180 转义、JSON 类型保全与 bigint 精度保护、GFM 转义）。
- **回滚点**：B3 行为若被否决，恢复 `buildCandidates` 中被删除的 `if (!info.scopeList.length) { … ix.colBySearch … }` 块即可（见 git diff），其余改动独立。
- **提交建议**：冒烟通过后按惯例 `feat: v2.4.0 — 结果网格导出 CSV/JSON/Markdown；补全列候选严格限定当前语句`。
